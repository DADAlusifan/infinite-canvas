# Windows 桌面版

仓库新增 Tauri 2 的 Windows x64 安装版工程，复用现有网页界面。桌面端使用 SQLite 保存业务记录和配置，媒体、缩略图及插件二进制保存为普通文件。网页版继续使用浏览器本地存储。

当前交付为工程和安装配置。尚未执行 Rust 编译、桌面构建或 Windows 安装验收；下面的命令供开发者执行。完整人工验收清单见[待测试事项](/zh-CN/docs/progress/pending-test)。

## 开发与打包

开发机需要安装：

- Windows x64 和 Microsoft Edge WebView2 Runtime。
- Visual Studio Build Tools 的「使用 C++ 的桌面开发」工作负载与 Windows SDK。
- Rust 的 MSVC 工具链及 `x86_64-pc-windows-msvc` 目标。
- Bun，用于安装前端依赖、启动 Vite 和运行 Tauri CLI。

具体系统准备参见 [Tauri Windows 前置要求](https://v2.tauri.app/start/prerequisites/#windows)。在仓库根目录打开 PowerShell：

```powershell
cd web
bun install
bun run desktop:dev
```

开发命令会启动 `http://localhost:23147` 的 Vite 服务。已有进程占用该端口时，先处理端口占用；不要关闭用户正在使用的浏览器页面，也不要通过更换端口查找原浏览器数据。桌面开发环境和正式版会拒绝共用同一个数据目录。

生成安装包：

```powershell
bun run desktop:build
```

命令会从根目录 `VERSION` 同步桌面应用版本，执行前端构建与 Rust 发布构建，并以 `x86_64-pc-windows-msvc` 为目标生成 NSIS 安装包。默认产物目录为 `web/src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`，自定义 Cargo 输出目录时以实际输出为准。

安装配置采用当前用户安装，支持中文与英文安装界面。终端用户无需安装 Bun、Node、Rust 或启动 Vite；缺少 WebView2 时，安装器配置为下载其引导程序，因此首次安装可能需要联网。首版不提供便携版、自动更新或内置 Agent 运行环境。

## 首次启动与数据目录

首次启动会打开原生文件夹选择框，可选择 D 盘中的专用空文件夹，例如 `D:\CanvasData`，或打开有效的已有桌面数据目录。不要选择包含其他文件的普通项目目录。数据目录不存在、不可访问、损坏或版本未知时，应用应提示错误并保留原数据，不创建空库替代。

应用标识固定为 `com.dadalusifan.infinitecanvas`。系统配置目录只保存定位数据目录的小型启动配置；主要内容位于所选目录：

| 内容 | 位置 |
| --- | --- |
| 业务记录、模型配置、媒体索引 | `data.sqlite3` 及 SQLite 运行文件 |
| 媒体、缩略图、插件二进制 | `media/`，由应用生成文件名并管理索引 |
| 未完成的文件写入 | `staging/` |
| WebView 缓存 | `cache/webview/` |
| 数据格式与开发/正式环境标记 | `infinite-canvas.json`、`desktop-environment.json` |

安装位置与数据位置分别设置。浏览器原有 IndexedDB 不会自动搬入桌面目录；换用桌面版也不会自动删除 C 盘里的浏览器数据。操作系统、WebView2 Runtime 和安装器自身仍可能使用系统盘。

不要直接改名、移动或删除 `media/` 中的文件，应用不会自动追踪这些操作。

更换桌面数据目录时，打开「设置 → 本地存储 → 更改数据目录」，从下拉菜单选择：

- **复制到新空目录**：复制全部业务记录、受管媒体、预览及插件文件，包括暂时未引用的文件。原目录保留，不复制 WebView 缓存和未管理文件。
- **切换已有目录**：打开同一开发或正式环境中的有效桌面数据集，不与当前数据合并；此模式不能选择空目录。

通过原生文件夹对话框选择目标并确认后，应用自动重启进入新目录。操作前完成待保存队列，维护期间阻止生成和编辑。当前目录、父子路径、跨环境或损坏数据、缺失媒体、被占用目标均应拒绝；取消或失败不改变启动定位，未完成目标不能作为有效数据目录打开。完整备份仍可用于跨机器传输和浏览器迁入，更改桌面目录不再要求先手动导出备份。

目录复制与切换仍待 Windows 实机验收，包括文件占用、操作中断和重启；Bun 行为测试及模拟不能替代桌面验证。

## 从浏览器完整迁入

1. 用原来的 Chrome/Edge 用户配置打开实际保存画布的地址。`localhost:3000`、`localhost:23147` 和 `127.0.0.1` 是不同的浏览器存储来源，需在正确地址导出。
2. 等待生成、同步、导入等操作完成，打开「设置 → 本地存储 → 完整备份」，选择导出位置。备份期间暂停编辑，关闭其他同源编辑页面可减少并发修改；检测到数据变化会取消本次导出。
3. 在桌面版相同设置页选择完整导入，通过原生对话框选择备份包和一个新的空目录。当前桌面目录不能作为导入目标。
4. 等待完整校验和写入。完成后检查记录数、文件数与目标目录，确认重启切换；也可以稍后再切换，或取消待切换状态后选择其他目录（已导入文件保留）。只有确认切换才更新启动配置，原浏览器数据和原桌面目录保留。
5. 重启后检查画布、素材、生成历史、渠道、模型尺寸、脚本及插件，再继续创作。

完整备份使用 ZIP64 流式写文件，包含已持久化的业务记录、偏好、原件、预览、暂未引用的媒体及插件私有数据。只保存远程 URL 的记录保留原地址，不会因为备份而自动下载。外部 Agent 工作区与对话文件、正在执行的 JavaScript、会话临时状态和内存撤销历史不属于备份内容。

浏览器完整导出要求 Chrome/Edge 提供本地文件写入与数据库枚举能力；不支持时会提示，不回退为把整个媒体库装入内存。损坏包、未知格式、缺少被引用文件、冲突内容、空间不足或取消操作，都不应覆盖原数据。中断后留下的暂存目标不能作为完整数据目录打开。

完整包包含 API Key、Agent 连接凭据及配置，不是脱敏包，也未加密；请把它保存在自己控制的位置。导出与导入在本机进行，不会自动上传备份。原有配置 JSON、画布 ZIP、素材 ZIP 与 WebDAV 保持各自格式，完整备份是单独的入口。

## 空间统计与手动清理

桌面「本地存储」显示当前目录、数据库、媒体、缩略图、插件文件与待删除内容的占用，提供打开目录、扫描和定位文件入口。

删除画布节点、素材或生成记录只移除业务引用。需要释放空间时：

1. 等待生成、导入和同步完成，点击扫描未引用文件。
2. 核对候选文件数、大小和明细，必要时先导出完整备份。
3. 明确确认清理；应用在执行前再次核对引用与数据版本。扫描后内容变化时需要重新扫描。

其他画布、素材、生成记录、插件数据、当前撤销历史和进行中任务使用的文件应保留。清理只处理索引管理的文件，不删除目录中的未知文件。媒体被外部删除时会显示缺失错误；需要从备份恢复原文件，不能用空数据覆盖记录。

## 内置代理与外部 Agent

桌面内置代理随进程启动和退出，只监听带会话凭据的本机回环地址，不需要另开 Node 代理。模型内置请求及调用脚本的 `http`、`request` 和注入的 `fetch` 使用该入口。显式 `window.fetch`、独立 Worker 与 WebSocket 仍遵循 WebView 原有网络行为。

「本地代理」页在桌面端提供三种出站模式：

- **系统代理**：默认读取 Windows 系统静态代理设置。
- **直连**：直接访问目标服务。
- **手动代理**：使用填写的代理地址。

首版不执行 PAC/WPAD 自动代理脚本；系统仅配置自动代理时会提示选择手动代理或直连。代理连接失败不会静默转为直连。上传、SSE、取消、重定向、签名 URL 和视频 Range 请求仍需按照待测试清单验证；代理可用不等于模型服务已验收。

Agent 继续连接外部 Canvas Agent。需要自行安装并启动原有 Agent 及对应 CLI，再配置连接地址和凭据；桌面版不打包 Node、Codex CLI、Claude CLI，也不迁移它们的外部工作区与历史文件。

## 验证范围

实施阶段仅运行有业务意义的 Bun 测试；没有运行语法检查、Rust 测试、编译或构建。安装与升级、WebView2 中文输入、主题、缩放、拖放、剪贴板、视频播放截帧、真实代理及大媒体压力场景需人工验收。真实付费生成需单独确认，不把本地模拟结果视为服务商接口验收。
